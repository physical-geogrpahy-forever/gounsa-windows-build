# GEOtopSed — published 2016 erosion extension versus nominal code repository

Original Zi et al. (2016), *Environmental Modelling & Software*, 83:310–325, https://doi.org/10.1016/j.envsoft.2016.06.004 . GEOtop catchment sediment extension, Dripsey Ireland; 15km2 study, 3D Richards subsurface, *directional kinematic surface routing*, sediment detachment and deposition. Catchment relative bias runoff -1.2%, sediment yield -22.4%. Not true free XY two-direction shallow-water momentum nor shown computational 5–10cm.

GEOtop official https://github.com/geotopmodel/geotop directs to published erosion extension nominal repository https://github.com/TanZiTT/GEOtopSed . Connected source HEAD master tree 95 files. Actually read GEOtop/vegetation.c::canopy_rain_interception(LSAI,..) and GEOtop/energy.balance.c lines413–419, which route canopy water below canopy. But the HEAD source tree has NO sediment solver-named files; directly inspected GEOtop/water.balance.c, geotop.c, input.c, output.c, none revealed rainfall sediment detachment/deposition call. Cannot claim this nominal repository proves exact published sediment engine compiled/usable. Other code distribution may exist but is not verified here. Avoid equating software name with sediment executable.

Scientific verdict for Gounsa: LAI canopy source yes; sediment paper yes; exact working shared canopy+sediment open source in inspected repo unverified; surface 1D directional kinematic, not desired freely spreading XY, and no 5–10cm valid mesh. Not main model. Source paper and git reviewed but no native compilation.
